# 클린 코드 컨벤션

현재 백엔드의 Java와 Spring Boot 코드를 기준으로 한다.

## 이름과 형식

- 클래스는 `PascalCase`, 변수와 메서드는 `camelCase`, 상수는 `UPPER_SNAKE_CASE`를 사용한다.
- 이름은 축약어보다 역할과 의미가 드러나게 작성한다. 예: `userList`, `findUserById`
- 메서드는 동사로 시작하고, 참·거짓 값은 `isActive`, `hasPermission`처럼 읽히게 작성한다.
- 들여쓰기와 공백은 팀에서 합의한 포맷터로 통일한다.

## 책임과 구조

- 클래스와 메서드는 각각 하나의 명확한 역할을 갖도록 작성한다.
- 컨트롤러는 요청과 응답을 처리하고, 서비스는 비즈니스 로직을 담당하며, 저장소는 데이터 접근을 담당한다.
- 중복되는 비즈니스 규칙은 한곳에 모으되, 단순히 코드가 비슷하다는 이유만으로 성급하게 추상화하지 않는다.
- 요청과 응답에 필요한 데이터는 DTO로 표현하고, 불필요한 내부 정보가 외부에 노출되지 않도록 한다.

## 오류와 주석

- 예외를 무시하지 않고 호출한 쪽이 이해할 수 있도록 적절히 처리한다.
- 로그에는 원인 파악에 필요한 정보를 남기되 비밀번호와 개인정보는 남기지 않는다.
- 주석은 코드가 무엇을 하는지 반복하기보다 코드만으로 알기 어려운 이유나 제약을 설명한다.
- 사용하지 않는 코드와 주석 처리된 코드는 남겨두지 않는다.

## 테스트와 DB

- 주요 비즈니스 규칙과 오류 상황을 테스트한다.
- 테스트 이름은 조건과 기대 결과가 드러나게 작성한다.
- 기존에 적용된 Flyway 마이그레이션 파일은 수정하지 않고 새 파일을 추가한다.
- 새 마이그레이션 파일은 `V20261109163000__create_users.sql`처럼 KST 기준 타임스탬프를 버전으로 사용한다. 병합 전 다른 마이그레이션과의 버전 중복 및 적용 순서를 확인한다.
